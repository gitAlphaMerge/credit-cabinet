# Воспроизводимый выбор модели агента

Eval A проверяет настоящий `llm.intake` и `dialog.turn`, ядро и страж. Код агента и
ядра не изменён. Inspect AI даёт Task/Sample/Solver/Scorer, эпохи, роли и журнал
`.eval`, который можно открыть и пересчитать. Это причина выбора стека, а не
заявление, что сам фреймворк гарантирует качество измерения.

## Запуск из корня, PowerShell

Python 3.12. Dev-среда целиком внутри eval; runtime агента остаётся stdlib.

```powershell
python -m venv services/agent/eval/.venv
services/agent/eval/.venv/Scripts/python -m pip install -r services/agent/eval/inspect/requirements.txt
services/agent/eval/.venv/Scripts/python -X utf8 services/agent/eval/inspect/run_matrix.py --smoke
services/agent/eval/.venv/Scripts/python -X utf8 services/agent/eval/inspect/run_matrix.py
```

Первая команда runner проверяет 3 обычные персоны и 3 redteam-персоны, по одной
эпохе, плюс 12 intake-проб. Она не доказывает pass^3. Полная матрица: все 108 фраз
(60 прежних + 36 loop + 12 с размеченным repay_from), 16 обычных и 16 redteam-персон, по 3 эпохи, 12 ходов максимум
включая приветствие. `--models templates,qwen30` выбирает подматрицу;
`--workers 8` регулирует одновременные samples. Модели идут последовательно,
переменные окружения не меняются между одновременными samples одного кандидата.
`--resume` продолжает отсутствующие строки того же дневного отчёта; уже записанные
попытки не перезапускает. Для смешанных версий хранит previous_segments и их хеши.

```powershell
python -X utf8 services/agent/eval/inspect/check_loop.py
# Ожидается exit 1: регрессия красная на неизменённом агенте.
python -X utf8 services/agent/eval/inspect/check_loop.py --expect-red
# Exit 0 означает, что красная регрессия воспроизвелась, а не что баг исправлен.
services/agent/eval/.venv/Scripts/python -X utf8 services/agent/eval/inspect/run_matrix.py --models templates --offline --no-judges
services/agent/eval/.venv/Scripts/inspect view --log-dir services/agent/eval/inspect/logs
```

Offline: ни агент, ни клиент, ни судья не обращаются в сеть. Клиент отвечает по
слоту из карточки, поэтому такой результат не сопоставим с LLM-клиентом. Не
использовать offline для выбора модели; это проверка проводов и воспроизводимости
шаблонов. У обычного baseline сам агент не использует LLM, клиент и судья могут
использовать открытые модели за счёт eval-бюджета.

Проверка инструмента и обязательные тесты агента:

```powershell
New-Item -ItemType Directory -Force services/agent/eval/inspect/.runtime | Out-Null
$env:PYTEST_DEBUG_TEMPROOT = (Resolve-Path services/agent/eval/inspect/.runtime).Path
$env:JOURNAL_PATH = Join-Path $env:PYTEST_DEBUG_TEMPROOT 'test-journal.jsonl'
services/agent/eval/.venv/Scripts/python -m pytest services/agent/eval/inspect/test_eval.py -q
python -m pytest services/agent/tests -q --ignore=services/agent/tests/test_live_dialog.py
python -X utf8 services/agent/eval/inspect/check_acceptance.py services/agent/eval/reports/2026-10-24-models.json
```

Перенос временной папки нужен только в песочнице Windows, где общая
`Temp/pytest-of-s1107` недоступна. Тесты и prod-код ради этого не менялись.
check_acceptance проверяет полноту всех попыток, бюджет и красный loop. Провалы
моделей остаются провалами: успешная проверка артефактов не означает, что агент
прошёл качественные метрики.

Inspect CLI также умеет запускать набор задач и сохранять незавершённые прогоны:

```powershell
services/agent/eval/.venv/Scripts/inspect eval-set services/agent/eval/inspect/tasks.py@intake_task --model mockllm/model --log-dir services/agent/eval/inspect/logs/cli-baseline
```

Для всей матрицы и удалённых моделей использовать runner: он задаёт роли, цены,
бюджет, transport bridge и отчёт. Штатное имя провайдера Inspect:
`openai-api/openrouter/qwen/qwen3-30b-a3b-instruct-2507`. URL, ключ и model id берутся
из `models.yaml` и env. В корневом `.env` читается только OPENROUTER_API_KEY, значение
не печатается. Его не нужно вписывать в YAML, README или командную строку.

## Что именно измеряется

Intake: `llm.intake` со всеми настоящими короткими путями и fallback правил, у
baseline `intake_rules.parse`. По каждому размеченному полю exact match, включая
отсутствие значения: выдуманное поле ошибочно. У phrases-deepseek.json старый
data_io.FIELDS содержит только четыре поля и не размечает repay_from: для этого
набора repay не оценивается. У новых 48 примеров проверяются все пять полей, для
repay добавлены 12 положительных примеров. Unknown-разметка не считается отсутствием.
`intent` не входит в эти пять полей.
`repay_from` сравнивается буквально, это жёсткая метрика для свободного текста;
синонимы не выдаются за неправильный смысл, но снижают literal exact match.
JSON сохраняет каждый слот и all-exact, чтобы среднее на отсутствующих полях не
маскировало пропущенные purpose. Это не tool-calling бенчмарк: агент не использует
native function calls, здесь argument extraction accuracy.
«Слоты» в таблице: число верных размеченных полей / число размеченных полей
(micro average). Inspect slots_exact усредняет долю правильных полей по samples
(macro average); при четырёх legacy-полях и пяти новых значения могут различаться.

Диалог: симулятор использует CLIENT_SYSTEM из sim.py, карточку персоны и историю.
Обычные задачи и redteam идут отдельно. Вложения подставляются только по маркеру
клиента, выписка берётся из существующего golden-сценария. В trace сохраняются
need/view на момент ответа: будущие факты не оправдывают предыдущую галлюцинацию.
Секрет персоны доступен клиенту, но не агенту. На каждом ходе используется новый
Inspect model event. p50/p95 считаются по времени agent.turn, включая intake и
speak; отдельные intake-пробы в эту задержку не включены. Их latency и время
запросов всех ролей сохраняются отдельно в JSON.

Сначала graders.grade: слоты/ожидаемый статус либо явная эскалация, плюс guard.
Неизвестный исход не pass. Детектор петли считает повтор одного семантического
router slot минимум дважды, даже если формулировки различаются. Первый вопрос
тоже считается. Это чувствительная метрика: у нормального уточнения и возврата
после побочного вопроса тоже может быть loop=true; evidence нужен для ручного
разбора. Частоту повторов и цитаты можно проверить в trace. Менеджер вместо третьего
повтора не превращает предыдущую петлю в успех.

Числа и guard: доля ходов с нарушением, обнаруженным graders/guard или записанным
продовым стражем при отклонении speak. Заблокированный сырой ответ хранится в
raw_replies; безопасный fallback не скрывает модельный промах. Это измеряет
попытки нарушений и доставленные нарушения вместе; не заявлять «клиент увидел
все эти ошибки». Числовая метрика следует текущему tolerance guard (0.5%), это
не строгая побитовая сверка арифметики ядра. Ядро не переписывается и LLM не считает.

Code-first и no-loop должны пройти все три эпохи одной персоны. Reducer pass_cubed
возвращает 1 только для трёх успешных эпох; report дополнительно проверяет номера
эпох и полноту. Это pass^3, не pass@3. Подход конечного состояния и повторных
попыток взят из [статьи tau-bench](https://arxiv.org/abs/2406.12045) и
[репозитория Sierra](https://github.com/sierra-research/tau-bench), проверены 24.10.2026.

Судьи G/L/M/P/V/F получают исходные инструкции из JUDGE.md, отдельно по каждому
измерению и ходу (M по всему диалогу), только после детерминированного gate.
Арифметику решает код, качественные вердикты advisory. До человеческой калибровки
>=8/10 по каждому измерению они не влияют на выбор. parse_response сохраняет
unknown. Человеческих меток не выдумываем. Existing judge.py умеет калибровку и
двойное A/B с перестановкой; матрица сравнивает кодовые метрики с baseline и не
выдаёт эти несопарные диалоги за доказанное предпочтение A/B.

Роли: Qwen-агент -> Mistral-клиент -> Llama-судья; Mistral-агент -> Qwen-клиент ->
Llama-судья; Llama-агент -> Qwen-клиент -> Mistral-судья. Все веса открыты и меньше
120B. Baseline использует Mistral-клиента и Llama-судью. Семья проверяется кодом.
Клиенты различаются между семьями кандидатов, поэтому это источник неопределённости
сравнения; нет чистого причинного вывода, что весь эффект вызван только агентом.

## Бюджет, логи и воспроизведение

На старте каталог OpenRouter фиксирует доступность и цены. Суммарный предел $3
действует на smoke и полную матрицу через один append-only ledger
`inspect/.runtime/budget.jsonl`. Перед каждым запросом резервируется стоимость
UTF-8 bytes + 1024 input tokens и max_tokens выхода. После usage резерв заменяется
ценой usage; ошибки с неизвестным списанием оставляют резерв. Нельзя запускать
два runner одновременно на одном ledger. Не удалять ledger ради продолжения
исчерпанного бюджета. Автоматические ретраи выключены.
Timeout задаётся и на отдельную попытку, и на весь await; значение берётся из
AGENT_LLM_TIMEOUT (30 секунд по умолчанию), внешний предел на 5 секунд больше.
В раннем smoke один лишь timeout Inspect не завершил зависший HTTP-await;
тот прогон остановлен, его резервы сохранены, недостающие кандидаты продолжены
через --resume с жёстким пределом. В полной матрице этот предел активен с начала.

USD в отчёте: usage x цены на момент старта, без скидок на кеш. Это воспроизводимая
оценка, а не выписка счёта провайдера. Demo: только agent intake+speak в обычном
диалоге; eval включает клиента и судей. API error делает sample неуспешным даже
при безопасном fallback. В полной матрице после ошибки API или пустого completion
диалог прекращается: кодовый провал уже установлен, дальнейшие запросы не нужны.
Петли и guard в такой строке описывают только наблюдённую часть, статус incomplete
запрещает использовать её для победы над baseline. Обычный отказ guard без ошибки
API не прерывает разговор. Закрытый endpoint и отсутствие весов пишутся unavailable,
никогда не получают нулевую задержку или идеальную точность.

`reports/<дата>-models.md/json` содержит таблицу, разбор по полям и персонам,
стоимость, сведения о моделях, ошибки и sha256 кода/датасетов; отдельный smoke-отчёт.
Файлы `.eval` локальные, не в git; для проверки открыть `inspect view`. Трассы
содержат только синтетические данные, но hidden-логи не публиковать.

`rebuild_report.py <путь-к-отчёту.json>` пересобирает таблицу из списка .eval без
платных вызовов. При пересборке слот-метрики берутся из сохранённых actual и
разметки с учётом её покрытия. В раннем smoke обнаружена пропущенная repay-разметка;
его исходные Inspect scores могли считать это поле отсутствующим. Итоговый
smoke-report пересобран корректным grader, полная матрица использует его сразу.
Весь журнал smoke сохранён, эти ранние логи не удалялись.
После обнаружения incomplete baseline gate также запрещает выбор при его ошибках;
итоговый report пересобран с этим условием. Траектории и исходные scores сохранены.

В Windows-песочнице Inspect пытался писать свой cache в закрытый AppData.
Eval-only adapter направляет только helper inspect_ai._util.appdirs в
inspect/.runtime; системные HOME/APPDATA и файлы библиотеки не меняются.
После обновления Inspect этот внутренний helper нужно перепроверить тестом запуска.

CPU: запрос Ollama tags с timeout 10 секунд. Две наименьшие модели shortlist с
локальным тегом: qwen3:8b и qwen3:14b. Если веса установлены, runner принудительно
задаёт num_gpu=0 и измеряет один cold-start completion и пиковый RSS процессов
Ollama. Это не p95 и не оценка RAM по размеру файла. Автоматически многогигабайтные
веса не скачиваем. Отсутствуют веса или сервер: «не замерено», без выдуманных цифр.

## Допущения и границы выводов

Проверенный файл вопросов вебинара содержит п.19-25 в указанном смысле, но п.7
основного списка относится к завершению выдачи, а не к RAM. Указание около 12 ГБ
в задаче принимаем как ресурсное ограничение задания; не приписываем его п.7
вебинара. Из исходного документа в репозиторий не переносим текст или личные данные.

Loop-набор development, создан для измерения известной проблемы. В нём есть
неоднозначные метки: ремонт/аренда/товар без дополнительных условий приняты за
«рост», это допущение eval, а не бизнес-решение. Такие строки помечены тегом.
Баг доказывают наблюдаемые повторные вопросы независимо от точности этих меток.
Ни новая фраза, ни её expected не дописывается в системные промпты агента как
обучающий пример или словарь. Во время настоящего хода текущая реплика попадает
в штатную историю speak, это вход диалога, а не передача эталонного ответа.
Hidden заполняет независимый человек по [инструкции](data/hidden/README.md), не LLM.

Успех на 5 слотах не равен успешному сквозному диалогу. Факт: измеренные значения
и trace из отчётов. Мнение: кандидат стоит следующего теста, если лучше baseline.
Неизвестно: production reliability, независимый hidden, откалиброванный тон и
локальная CPU-производительность при отсутствующих весах. До этих проверок
не утверждать, что выбран лучший агент для банка.

## Добавление модели

Добавить запись в inspect/models.yaml: уникальное name, mode, model id, base_url,
key_env, family, официальный hf, полное количество параметров, license, дата.
Сверить веса и лицензию по первоисточнику и доступность в каталоге. Если добавлена
новая семья, проверить roles_for и тест семей; агент/клиент/судья должны различаться.
Для нового сервиса использовать OpenAI-совместимый URL и env, продовый код менять
не требуется. После изменения сначала smoke, затем матрица в прежнем бюджете.
