# Метки человека

UTF-8 JSONL: одна оценка одного измерения в строке.

```json
{"dialog":"cash_gap_b:1","n":2,"dimension":"L","verdict":"fail","note":"Не ответил про плитку"}
{"dialog":"cash_gap_b:1","n":null,"dimension":"M","verdict":"pass","note":"Не переспрашивал"}
```

`dialog` — уникальный `id` из JSONL, переданного через `--trace`. Либо путь к файлу
с одним диалогом (относительно файла меток). `n` — номер ответа агента с 1, включая
приветствие; для M — null. Измерения: G/L/M/P/V/F. Вердикт: pass/fail/unknown.
`note` — объяснение человека, не инструкция судье. Метки не передаются в промпт.

Запустите `python eval/play.py --persona cash_gap_b --templates`, сыграйте клиента,
поставьте оценки и сохраните комментарии. Файл `traces/human-*.jsonl` содержит ходы;
пронумеруйте их с 1 и разнесите общую оценку по измерениям вручную. Enter/«-» сами
по себе не дают метки всех шести свойств. Для M оценивается весь диалог.
Пример калибровки: `python eval/run_all.py --calibrate labels.jsonl --trace traces/human-....jsonl`.
Для play.py идентификатор диалога — имя файла без расширения.

Нужно минимум 10 размеченных случаев для каждого измерения и согласие не ниже 80%
(8 из 10). Желательно поровну pass и fail, с примерами «должен» и «не должен»;
не размечайте один случай повторно ради порога. До допуска вердикты — подсказки,
а provisional pass^k не означает допуск судьи.

Метки также придут из фидбека клиентов: причины 👎 — коды G/L/M/P/V/F,
см. `context/feedback.md` (если файла ещё нет в этой ветке, это ссылка на будущий
контракт). Перед переносом фидбека проверьте измерение и привязку к диалогу/реплике.
