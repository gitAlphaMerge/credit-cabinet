# Фидбек клиента в чате с агентом

Решение архитектора 20.10. Код пишется под этот файл.
Зачем: оценки ребят и клиентов становятся метками для калибровки судьи (`services/agent/eval/JUDGE.md`), а не просто лайками.
Как у Claude и ChatGPT: 👍/👎 под каждым ответом, на 👎 причина и текст. Точные списки их причин по первоисточнику не подтверждены, поэтому причины свои: каждая = измерение судьи.

## Под каждым ответом агента

👍 / 👎, повторный клик снимает оценку, смена оценки перезаписывает.

На 👎 раскрывается панель (можно несколько причин), поле «Что было не так?» необязательно:

| Причина (текст кнопки) | Измерение судьи |
|---|---|
| Выдумал или ошибся | G |
| Не ответил на мой вопрос | L |
| Переспросил то, что я уже говорил | M |
| Пообещал лишнее или нарушил правила | P |
| Звучит как робот | V |
| Непонятно, что делать дальше | F |
| Другое | — |

На 👍 необязательное поле «Что понравилось?».

## В конце разговора

Карточка появляется, когда агент выдал расчёт (`status` в ответе агента не `collecting`) или клиент нажал «Завершить разговор». Один раз на чат, можно закрыть крестиком.

1. «Насколько вы согласны: ИИ-помощник помог мне легко разобраться с задачей». Шкала 1–7, подписи краёв «совсем не согласен» / «полностью согласен» (CES 2.0, CEB/Gartner).
2. «Что сделать проще?» — свободный текст, необязательно.

CSAT и NPS рядом не спрашиваем: одна метрика, без опросника.

## Где лежит

SQLite кабинета (volume `alfa_data`), таблица `feedback`: `id, user_id, chat_id, message_id (null для итоговой), kind ('message'|'conversation'), rating ('up'|'down' или 1–7), reasons (JSON массив кодов G/L/M/P/V/F/other), text (≤ 1000), agent_mode (team-agent|agent-offline|…), created_at, updated_at`. Уникально (user_id, message_id, kind).
Реплики разговора уже лежат в состоянии пользователя; трейсы агента (слоты, цель хода, нарушения стража) в `agent_state/agent.log` по `session_id = chat_id`.

## Выгрузка для команды

`GET /api/admin/feedback.jsonl` с заголовком `Authorization: Bearer <FEEDBACK_EXPORT_TOKEN>`. Нет токена в окружении → 404, неверный → 401, сравнение за постоянное время.
Строка = одна оценка + реплики чата до оценённого ответа включительно. Перед выгрузкой из текста вырезаются паспорт, ИНН, СНИЛС, карты, телефоны, email (`[скрыто]`). user_id в выгрузке = sha256, телефона нет.
Токен: секрет GitHub `FEEDBACK_EXPORT_TOKEN`, деплой кладёт в `.env`, Compose передаёт сайту Толи только эту переменную.

## Вся история у Саши

Саша хочет иметь у себя всю историю, а не только оценённые ответы.

- `GET /api/admin/history.jsonl?since=<ISO>` (тот же токен): строка = один чат целиком: `chat_id`, `user` (sha256), даты, все реплики клиента и агента с `mode`, `status` агента, все оценки этого чата и итоговая карточка, плюс `agent_trace` (цели хода, слоты, интент, нарушения стража). Чаты без оценок тоже. Вырезание ПДн как выше. `since` отдаёт чаты, изменённые после даты.
- `agent_trace` сайт берёт у агента по внутренней сети: `GET http://agent:8090/admin/sessions?ids=<chat_id,...>` с тем же Bearer-токеном (агент читает `FEEDBACK_EXPORT_TOKEN` из своего `.env`; нет токена → 404). Наружу порт агента по-прежнему закрыт. Агент недоступен → `agent_trace: null`, выгрузка не падает.
- `scripts/pull_history.py --base http://158.160.212.36:4173`: токен из `FEEDBACK_EXPORT_TOKEN` в env или `~/.config/credit-cabinet/token` (не из аргумента), пишет `~/projects/credit-cabinet-history/history-<дата>.jsonl` и `feedback-<дата>.jsonl`, помнит последний `since` в `state.json`, повторный запуск докачивает только новое. Папка вне репо и вне синхронизируемых папок.
- Данные на сервере живут в volumes `alfa_data` и `agent_state` и переживают деплой; выгрузка не удаляет ничего на сервере.
