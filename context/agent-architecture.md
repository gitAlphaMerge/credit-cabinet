# Архитектура агента

Источник правды по агенту. Код: `services/agent/`. Решения: workflow 17.10, eval 18.10, стенд 19.10.

## Что это

Агент не автономный: это workflow, где LLM стоит только там, где нужен язык, а всё, что считает деньги или решает, сделано кодом.
Ядро Лизы считает цифры и статус, агент спрашивает и объясняет, решение о кредите за банком.

```
клиент → [1 LLM-приёмщик] → [2 код-роутер: goal] → [3 ядро Лизы при готовности] → [4 speak] → [5 код-страж] → клиент
            intake_rules.py    dialog.py       core_http.py     llm.py              guard.py
            + llm.py (слоты)   next_slot()     → api → ml-model  explain_templates.py (откат)
```

1. **Приёмщик** (`intake_rules.py`, при ключе `llm.py`): из реплики достаёт слоты `purpose`, `amount_rub`, `term_months`, `repay_from` и намерение `answer_slot | side_question | identity | manager_request | pii | smalltalk`. Правила безопасности имеют приоритет над разбором свободного текста. Новое слово клиента перекрывает старое.
2. **Роутер** (`dialog.py`): код выбирает цель `ask:purpose`, `ask:amount`, `ask:repay`, `ask:term`, `ask:statement`, `explain`, `answer`, `manager`. Побочный вопрос получает ответ, текущий слот сохраняется в `return_slot` без увеличения числа попыток. Про ИИ отвечает честно; просьба о менеджере и третья неудачная попытка ведут к `manager`. История не даёт повторить предыдущую реплику дословно.
3. **Ядро** (`core_http.py` → `POST {AGENT_CORE_URL}/score`): тот же путь, что у сайтов, одно ядро на всех. На ноуте и в eval `core_local.py` зовёт `ml-model/app.py:decide()` без HTTP. Ошибка ядра = «посчитать сейчас не получилось», сессия не теряется.
4. **Голос каждой реплики** (`llm.speak(goal, ctx)`, temperature 0.7): системный промпт содержит `AGENT.md`, `PERMISSIONS.md`, активные факты клиента (новые сверху), последние восемь реплик, цель хода и разрешённые числа из `view` и слов клиента. `explain` сохранён как совместимый интерфейс, выдача клиенту проходит через `speak`. Без ключа или при ошибке используются заготовки той же цели из `dialog.py` и `explain_templates.py`.
5. **Страж** (`guard.py`): проверяет любую реплику LLM: разрешённые числа, обещания за банк, запрещённые термины, не больше одного вопросительного знака, длину до 450 символов, длинное тире, цифровые шаблоны ПДн. При провале заготовка заменяет реплику, нарушение остаётся в trace.

## Память

Сессия = состояние диалога (слоты, `view`, попытки, trace). Хранится в `SESSIONS` и на диске `AGENT_STATE_DIR/sessions/<sha256(session_id)>.json` (volume `agent_state`), запись атомарная. Выписка не хранится, только `sha256` и признак. Рестарт контейнера разговор не теряет.

Рабочая память: `state["history"]`, последние восемь записей `{role, text}`. Память клиента отделена от сессии: `memory.py`, `AGENT_STATE_DIR/clients/<sha256(client_id)>.json`. Без `client_id` межсессионной памяти нет. Факты не подставляются в слоты новой заявки автоматически: агент уточняет их актуальность.

После отправки HTTP-ответа обработчик обновляет факты под блокировкой клиента. При ключе один вызов `llm.chat(as_json=True)` получает последнюю пару реплик и активные факты, возвращает ADD/UPDATE/DELETE/NOOP. Без ключа правила записывают цель, запрошенную сумму, источник возврата и статус расчёта словами. Код отбрасывает ПДн, содержимое выписки, числа `view`, факты длиннее 200 символов и неизвестные id. UPDATE/DELETE сохраняют прежний текст в history; активных фактов не больше 30, в первую очередь архивируются старые progress. Запись атомарная, tmp + rename; ошибка логируется и не влияет на ответ. «Забудь меня» и «удалите мои данные» помечают все факты deleted и убирают text/history. Правила: `services/agent/MEMORY.md`.

## Модели

- Агент: DeepSeek (открытые веса) через `AGENT_LLM_URL`, ключ `DEEPSEEK_API_KEY` в `.env` сервера (кладёт `deploy.yml` из секрета). Без ключа работает на шаблонах, это и есть проверяемая версия по ограничениям кейса (без платных API).
- Клиент в симуляции: Qwen. Судья в eval: модель другого вендора, чем агент и клиент.

## Eval

`services/agent/eval/`: уровни 0–4.
- `sim.py`: персоны-клиенты (Qwen) против агента, сценарии из `data/personas*.json`.
- ред-тим: персоны-провокаторы (`personas-redteam-*.json`).
- `judge_pack.py`: пакет для судьи, бинарные ok/fail с цитатой, калибровка по меткам человека (нужно ≥8 из 10 совпадений).
- `tgbot.py`: eval-бот в телеге, люди играют персон, оценки в jsonl.
- Регрессии: `tests/test_dialog_regressions.py`, общие тесты `pytest services/agent/tests`.

## Стык с сайтами

- Сайт Толи → `TEAM_AGENT_URL=http://agent:8090` → `POST /turn {session_id, text, card, client_id?}` → ответ `{text, status, view}`. Необязательный `client_id` является строкой длиной до 200 символов, сайт передаёт id пользователя. Новый разговор с тем же клиентом получает активные факты уже на первом ходе. Агент недоступен = «Ассистент сейчас недоступен».
- `GET /health` = `{ok, llm, memory: true, started_at, turns}`. Наружу порт агента не открыт.
