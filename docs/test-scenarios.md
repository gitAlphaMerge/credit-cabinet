# Проверки и синтетические данные

Команды ниже описывают существующие проверки, а не утверждают, что они запущены при подготовке документов. Из корня репозитория, кроме команд с явным `cd`. Для runtime-проверок сначала поднимите Compose. Никакие тесты не требуют данных клиентов банка.

| Проверка | Команда | Зелёный результат |
|---|---|---|
| Ядро Лизы, golden | `python data/check_golden.py` | Все сценарии из `data/golden.json`, код 0 |
| Один golden | `python data/check_golden.py -k cash_gap` | Пройдены выбранные сценарии, код 0 |
| Самопроверка эталона | `python data/check_golden.py --reference` | Все golden; это не приёмка ядра Лизы |
| HTTP-обвязка ml-model | `cd services/ml-model` затем `python -m unittest discover -s tests -v` | Нет failures/errors, код 0 |
| Агент | `python -m pytest services/agent/tests` | Все тесты passed, код 0; pytest должен быть установлен в окружении |
| Frontend/API smoke | `python scripts/smoke.py --base http://localhost` | Все строки OK, код 0 |
| Кабинет smoke | `node hw/tolya/alfa-intellect/scripts/smoke.mjs --base http://localhost:4173` | Все строки OK, код 0; Node 24+ |
| Кабинет, unit/integration | `cd hw/tolya/alfa-intellect` затем `npm test` | Нет failed, код 0; нужны зависимости из lock-файла |
| Кабинет, сборка | В каталоге кабинета `npm run build` | TypeScript и Vite без ошибок, код 0 |
| Eval без LLM | `python services/agent/eval/run.py --runs 3` | Все сценарии pass^3, код 0; trace JSONL в eval/traces |

Для проверки ml-model команда выполняется из его каталога из-за прямого `import app` в тестах. Node-тесты используют встроенный test runner через tsx. `npm run verify` дополнительно проверяет форматирование, сборку и тесты. Установка пакетов при подготовке этой документации не выполнялась.

Smoke кабинета проверяет страницы, SQLite, регистрацию и мок-ИНН; на `/api/team-score` допускает как 200, так и корректный 502. Поэтому один зелёный smoke не доказывает доступность ядра: нужен успешный расчёт и golden. Health Go также проверяет сам шлюз, не ядро. Главная проверка фактического ядра: `python data/check_golden.py`.

## Golden и дополнительные сценарии

Источник ожиданий: [golden.json](../data/golden.json). Восемь сценариев: `cash_gap`, `cash_gap_small`, `equipment_leasing`, `seasonal_ok`, `enforcement`, `no_cashflow`, `short_history`, `cash_out`. Проверяются статус, инструмент, лимиты и причины по критериям check_golden. Выписки находятся в [data/synthetic](../data/synthetic/), генераторы рядом; label используется эталоном, а ядро должно классифицировать операции самостоятельно.

| Действие | Ожидание по коду |
|---|---|
| v2-чат, демо или свой CSV | `/api/score` возвращает decision/core/view; UI показывает цифры ядра |
| CSV без обязательных колонок | 422 с JSON error |
| JSON без нужды или анкеты | 422 |
| Неподдерживаемый Content-Type ядра | 415 |
| Недоступное ядро за Go | 502 с JSON, frontend остаётся доступен |
| Кабинет без cookie, `/api/state` | 401 |
| Поиск `9900000001` при EGR_PROVIDER=mock | demo=true, источник «синтетические данные (мок)» |
| Подтвердить lookup без свежего поиска | 409 |
| Загрузить fixture и подтвердить документ | confirmed=true, извлечённые поля сохранены |
| Повторить тот же файл | Тот же id, без второго документа |
| Пересчитать подбор с устаревшим expectedVersion | 409 |
| Создать заявку без обязательного подтверждения рисков | 422 |
| Повторная подача той же версии | Возвращается существующий lead |
| Обновить страницу кабинета | Профиль, чат, подбор и документы восстанавливаются из SQLite |
| Диалог кабинета с агентом | Сбор полей, просьба о выписке; полного расчёта через вложение HTTP пока нет |

Для ручного воспроизведения используйте [README](../README.md) и [requests.http](requests.http). В коллекции отдельные базы для кабинета, Go и внутренних сервисов; agent:8090 на хосте не опубликован.

## Eval агента

Архитектура и уровни: [источник автора](../context/agent-architecture.md). Регрессии входят в pytest, включая диалог и сохранение сессий.

- `python services/agent/eval/run.py --runs 3`: детерминированный сценарист, локальное ядро, контроль статуса/инструмента golden, полей и guard. Использует прямые вложения `dialog.turn`, поэтому не доказывает наличие передачи CSV по HTTP.
- `python services/agent/eval/play.py --templates`: список персон; `--persona <id> --templates` запускает ручной разговор без внешней LLM. Оценка человеком, автоматического «зелёного» результата нет.
- `python services/agent/eval/sim.py --runs 3`: клиент Qwen, агент на модели из `AGENT_LLM_MODEL` (в проверяемой версии Qwen); флаг `--source` выбирает набор провокаций. Требует разрешённой сети и провайдера, не нужен для автономной проверки жюри. Имена моделей в коде являются настройками endpoint, а не доказательством развёрнутых весов.
- `python services/agent/eval/judge_pack.py`: пакет из последнего sim-трейса для судьи другой семьи моделей. Судья отмечает ok/fail с цитатами, человек сверяет; целевая калибровка по архитектуре: не менее 8 совпадений из 10. Сформированный пакет сам по себе не означает успешную оценку.
- `tgbot.py`: вспомогательный eval-инструмент команды, не часть продуктового пути. Доступ к Telegram для проверки продукта не требуется.

## Данные и тест-учётки

Постоянных общих логина/пароля в коде нет. Не используйте реальные телефоны, документы или банковские данные.

1. Публичная страница `/demo` и `GET /api/public-demo?kind=ooo` доступны без регистрации; варианты `ooo`, `ip`, `idea`.
2. `POST /api/auth/demo {"kind":"ooo"}` создаёт отдельного синтетического пользователя со случайными идентификаторами и cookie. Состояние сохраняется в SQLite. Секрет для повторного логина пользователю не выдаётся.
3. Для повторного входа зарегистрируйте тестовую учётку: синтетический номер `+7 900 000-00-01`, пароль `DemoOnly-2026`, профиль из requests.http. При 409 номер уже занят, выберите другой синтетический номер. Формат: +7 и 10 цифр, пароль 8..128 символов. SMS/почта для регистрации не нужны.
4. Fixtures кабинета: `statement.csv`, `balance.csv`, `pnl-comparable.csv`, `pnl.pdf`, `model.xlsx`, `plan.docx`, `schedule.csv` в [fixtures](../hw/tolya/alfa-intellect/fixtures/). Генератор `npm run fixtures` вызывается Dockerfile при сборке.
5. Мок-реестр: `fixtures/egr-mock.json`; ИНН `9900000001`, `9900000002`, `990000000001`, `990000000002`. Посторонний ИНН не создаётся автоматически, ответ 404.

Проверка документов этой поставки: команда из задания проверяет YAML/OpenAPI и наличие файлов. Она не запускает сервисы, тесты или сетевые eval.
