# Альфа-Интеллект · автономный MVP Толи

Все исходники изолированы в `hw/tolya/alfa-intellect`, ветка `Толя`. Локальный продукт: публичный лендинг → две ветки анкеты → аккаунт → кабинет / чат / подбор / профиль. Реальных банковских действий нет.

## Запуск и проверка за 5 минут

Основной путь: корневой compose, Docker с Linux-контейнерами. Памятка: `docs/LAUNCH.md`. Из корня репозитория:

```sh
docker compose up -d --build api alfa-intellect
cd hw/tolya/alfa-intellect
node scripts/smoke.mjs --base http://localhost:4173
```

Открыть http://localhost:4173 или http://localhost:4173/demo. Команда поднимает
также `ml-model` по зависимости Go API. Сайт обращается к `http://api:8080`
внутри Docker, без `host.docker.internal`. Адаптер ядра: защищённый
`POST /api/team-score`. Обычный подбор в UI использует локальную демонстрационную
модель, это не результат ядра Лизы.

Первичная сборка требует заранее доступных Docker-образов и npm-зависимостей
(`npm ci` сохранён). Для ПК без сети подготовьте образы на машине сборки,
перенесите через `docker save` / `docker load`, затем запускайте:
`docker compose up -d --no-build api alfa-intellect`. Наличие `node_modules`
на хосте не заменяет зависимости внутри образа. Dockerfile закреплён на
`node:24.0.0-slim`, версии из `engines`. Smoke требует только Node 24 и stdlib.

Для проверяемой версии ключи и внешние сервисы не нужны. Корневой compose
не передаёт ключи, ЕГР работает в `mock`. Чат без ключей работает на шаблонах,
внешняя LLM не вызывается. OpenAI не входит в проверяемую версию. Если отдельно
подключаете LLM агента, используйте только разрешённые кейсом открытые веса.
Python-агент не упакован в образ сайта; его необязательное подключение остаётся
отдельным контрактом команды.

SQLite и документы сохраняются в volume `alfa_data` (`/app/var`). Перезапуск:
`docker compose restart alfa-intellect`. Логи: `docker compose logs --tail=80 alfa-intellect`.
Для другого порта задайте `ALFA_PORT` и передайте тот же порт в `--base`.
Сайт перезапускается автоматически. `/health` и `/api/health` возвращают 200 JSON:
`status`, `db: ok|fail`, `team_api: ok|down|not_configured`. Go API проверяется
с таймаутом 2 с, его отказ не делает сайт unhealthy. Отказ БД даёт `degraded`
и учитывается Docker healthcheck. Healthcheck сам по себе не перезапускает контейнер.
`depends_on: service_started` задаёт порядок запуска, недоступность уже запущенного
API не блокирует сайт. Отказ адаптера возвращает понятный JSON 502 за 30 с.

Smoke печатает OK/FAIL и возвращает exit 1 при ошибках. Создаёт синтетического
пользователя в выбранной базе, записи сохраняются. Недоступное ядро допускается
только как понятный JSON 502. Для полного стыка дополнительно убедитесь, что
`/health` показывает `team_api: ok`. Сумма лимитов корневого compose теперь
768 МБ: сайт добавляет заданные 256 МБ, существующие сервисы сохранены.

### Какие данные синтетические

`fixtures/egr-mock.json`: четыре вымышленные записи. Номера предназначены только
для мока, их контрольные цифры не подтверждают регистрацию:

| ИНН | Форма | Статус | ОКВЭД |
| --- | --- | --- | --- |
| 9900000001 | ООО | Действующая | 31.09 |
| 9900000002 | ООО | Ликвидирована | 46.73 |
| 990000000001 | ИП | Действующий | 62.01 |
| 990000000002 | ИП | Прекратил деятельность | 56.10 |

Ответ и UI показывают «синтетические данные (мок)», в том числе после сохранения
в профиле. Неизвестный номер даёт 404 с подсказкой. Мок выбирается без ключей
реестра или явно `EGR_PROVIDER=mock`. Для реального провайдера уберите `mock`
и задайте ключ. Сбой реального провайдера не подменяется моком. Публичное демо,
каталог ставок и подготовленные документы также синтетические, не являются
банковским решением или подтверждением сведений государственного реестра.

Локальный `compose.yaml` оставлен для отдельного запуска сайта. Его прежний
`TEAM_API_URL` с `host.docker.internal` требует настройки хоста на Linux;
основной путь этого адреса не использует. Для проверки используйте корневой compose.


## Запуск без Docker

Требуется Node.js **24+** и npm. Из корня репозитория:

```sh
cd hw/tolya/alfa-intellect
npm ci
npm run fixtures
npm run build
npm start
```

Откройте http://localhost:4173 . Для разработки с Vite и горячим обновлением: `npm run dev` (работает и при наличии `dist`). Для production-просмотра после изменения UI выполните `npm run build`, затем `npm start`. Ctrl+C останавливает сервер. Порт меняется `PORT=4174 npm start`.

Если порт занят прежним процессом, запуск завершится с кодом 1 и понятным сообщением. Сначала остановите прежний сервер либо выберите другой порт: два запуска не обновляют серверный код друг друга.

Без ключей всё приложение запускается. SQLite (`var/alfa.sqlite`) создаётся миграцией v1 автоматически, файлы хранятся в той же базе и изолированы по пользователю. `var/` в git не попадает. Для проверки: `npm run verify`. Для smoke-тестов используются отдельные временные БД, основная не очищается.

## Демо и сценарии

Публичное **http://localhost:4173/demo** открывается без регистрации и не создаёт пользователя, сессию, кредит или записи в вашей истории. Переключаются ООО, ИП и проект, кабинет, расчёт, пример переписки и документы; сумму/срок можно пересчитать на синтетических данных. Демо отсутствует в авторизации и обычном кабинете. Для своей работы пройдите трёхэкранную анкету и отдельную регистрацию: телефон в маске `+7 (999) 123-45-67`, пароль от **8 символов**, собственные русские ошибки и переключатель видимости. SMS отсутствует; это не банковская идентификация.

1. Пройдите анкету или откройте демо → профиль через имя компании.
2. Введите полный ИНН: 10 цифр для организации или 12 для ИП. Без ключей автозаполнение использует локальный мок из таблицы выше. С ключом и без EGR_PROVIDER=mock доступны API-ФНС или DaData. Ручное заполнение доступно всегда. Подтвердите найденные сведения перед сохранением. Мок явно помечен в ответе и профиле.
3. У любой из шести карточек нажмите «Загрузить», выберите файл, проверьте извлечённые поля и подтвердите. Для локальной проверки можно скачать шаблон с явно синтетическим примером и самостоятельно загрузить его через профиль или скрепку чата: хранилище одно. Автоматической подстановки примеров в профиль больше нет. Сканированный PDF без текстового слоя не поддерживается. Только подготовленные формы, до 8 МБ.
4. Подбор → финансовая задача и её уточнения → проверка известных данных бизнеса → результат. Измените продукт/сумму/срок, сравните версии одного подбора, обсудите в отдельном связанном чате и сохраните демо-заявку без повторного ввода телефона. Расчёты обычного кредита, линии и овердрафта различаются.
5. «Перейти к оформлению» → выгрузите JSON-досье, подтвердите тестовый контакт → сохраните локальную демозаявку. Ничего не отправляется в банк.
6. Единый кабинет — `/cabinet`: сетка прежнего кабинета с расчётами и интеграциями новой версии. `/cabinet-v2` и `/efficiency` открывают этот же экран, переключателей версий нет. Неизвестный долг показан прочерком, 0 ₽ — только после подтверждения отсутствия кредита. Кредит добавляется через договорные параметры и подтверждение, можно использовать график из профиля. Ставка, срок и дата погашения выделены в отдельные блоки. Компактный календарь открывается по верхней правой иконке ближайшего платежа: неподвижные стрелки, собственные списки месяца/года, даты платежей, состав суммы и обсуждение с агентом. «График погашения кредита» показывает остаток основного долга. Примеры только в публичном `/demo` и временном обучении; старые синтетические договоры сохранены в базе, но исключены из обычного кабинета и его расчётов.
7. Первое обучение: ровно шесть подсказок (финансирование; платежи и график; поток и коэффициенты; рекомендации и уведомления; агент; подбор). Учебные значения существуют только в UI, «Завершить»/«Пропустить» возвращают настоящие данные, сохраняется только флаг обучения. Повторный запуск — `?` в шапке.
8. По умолчанию кабинет занимает всю ширину, чат открывается кнопкой. В split view чат можно скрыть и восстановить, открыть отдельной страницей; ширина меняется мышью и клавиатурой. На узком экране — вкладки. В полном чате история независима, на телефоне это закрываемая панель с фокусом и затемнением. Quick Actions сразу отправляются и защищены от двойного клика.
9. Четыре показателя встроены в кабинет: DSCR, доля платежей в поступлениях, динамика выручки, рентабельность продаж. Значки ⓘ показывают формулу, смысл, источники и период при наведении, фокусе клавиатурой или нажатии. У DSCR границы 1,0/1,3; у остальных красно-зелёная шкала показывает направление, не выдуманный банковский норматив. Неизвестное значение — нейтральная шкала без маркера. «Хватит ли денег на платёж?» объясняет ожидаемый остаток и необходимые данные. Отдельной страницы показателей нет.

Отчёт нового UX-этапа: `docs/UI_REDESIGN.md`. Уточнения от 17.10: `docs/UI_REFINEMENTS_2026-10-17.md`. Анимации: `docs/MOTION_2026-10-17.md`. Чат: `docs/CHAT_REDESIGN_2026-10-17.md`. Финансовая методика: `docs/CABINET_V2_2026-10-18.md`. Единый кабинет: `docs/CABINET_UNIFIED_2026-10-18.md`. Уточнения: `docs/CABINET_POLISH_2026-10-18.md`. Читаемый ввод: `docs/NUMERIC_INPUTS_2026-10-18.md`. Проверка полей и русские ошибки: `docs/FIELD_VALIDATION_2026-10-18.md`. Подбор финансирования MVP 2: `docs/FINANCING_MVP_2026-10-18.md`. `npm run verify` проверяет форматирование, TypeScript, production build и 104 теста. При уменьшенном движении анимации отключены, приветственный переход сокращён; обычный вход не задерживается.

DSCR требует отдельного подтверждённого CFADS и методики, не подставляет чистый поток выписки. Прогноз требует остатка на начало известной даты и полного датированного плана на 30 дней; при отсутствии данных не вычисляется. Коэффициенты выручки и рентабельности используют поля подтверждённого ОФР; расширенный шаблон — `fixtures/pnl-comparable.csv`, ссылка есть в профиле. Статусы платежей не выводятся автоматически из прошедшей даты. Уведомления проверяются при входе/обновлении состояния, не являются круглосуточным мониторингом. Настоящее финансовое ядро команды этим изолированным слоем не подменено.

Чат: читаемая колонка до 824 px, сворачиваемая история с поиском и переименованием, три быстрых вопроса, единое поле со скрепкой и круглой кнопкой отправки. Enter отправляет, Shift+Enter переносит строку; высота поля растёт до 180 px. При загрузке документ получает компактную плашку над полем. Скрытие плашки **не удаляет документ** из профиля. Привязка плашек к диалогам хранится только в памяти текущего сеанса; сами документы и сообщения сохраняются в SQLite. Черновик сообщения сохраняется при смене режимов и закрытии панели, но не после обновления страницы.

Незавершённый подбор автоматически сохраняется в `sessionStorage` текущей вкладки: шаг, цель, динамические уточнения, сумма/срок и денежные параметры восстанавливаются после обновления страницы. Черновик привязан к аккаунту, удаляется при выходе и истекает через 24 часа; закрытие вкладки также завершает его хранение. Новый запрос не удаляет сохранённые подборы. Документы, пароли и переписка в это хранилище не попадают. При запрете браузерного хранилища анкета продолжает работать в памяти и предупреждает об ограничении. Сохранённые подборы, все версии условий, демо-заявки и документы остаются в серверной SQLite независимо от черновика. Миграция 2 добавляет отдельную таблицу внутренних досье демо-заявок; рабочие записи не удаляются.

## Интеграции

При необходимости создайте локальный `.env` по `.env.example` (секреты не коммитить):

- `OPENAI_API_KEY`: серверный ключ OpenAI, только экспериментальная разработка, не входит в проверяемую версию. При проверке оставить пустым. `AI_MODEL=gpt-5.4-mini`. Responses API и ограниченные функции чтения контекста, расчёта и предложения изменения (без сохранения до подтверждения). `AI_DAILY_CALL_LIMIT=20`. До 1800 выходных токенов и трёх API-вызовов на сообщение. Платные вызовы в ходе разработки не выполнялись. См. docs/DECISIONS.md для ссылок и стоимости на дату проверки. Реальные квоты зависят от аккаунта.
- `FNS_API_KEY`: серверный ключ стороннего сервиса API-ФНС (не прямой API государственной ФНС), метод `POST https://api-fns.ru/api/egr`. Данные ЕГРЮЛ/ЕГРИП, точное совпадение ИНН. Приоритет перед DaData. Документация: https://www.apifns.ru/api_help .
- `DADATA_API_KEY`: альтернативный серверный ключ DaData, `findById/party`, поиск головной организации. Документация: https://dadata.ru/api/find-party/ . Без ключей используется локальный мок; при сбое провайдера — 502, при отсутствии компании — 404. Ошибки реальных провайдеров не подменяются синтетическими сведениями, ключи не выдаются браузеру. После изменения `.env` перезапустите сервер. Регистрацию у провайдера, приобретение доступа и живую проверку ключа выполняет владелец аккаунта.
- `TEAM_API_URL`: адрес существующего Go-шлюза команды; `/api/team-score` — защищённый адаптер текущего контракта. Подбор здесь использует отдельную демонстрационную модель платежей. Он не выдаётся за боевое ядро Лизы и не меняет его.
- `COOKIE_SECURE=true`: для эксплуатации за HTTPS. По умолчанию localhost и `HttpOnly`, `SameSite=Strict`, срок 7 дней. Пароли scrypt с индивидуальной солью; cookie содержит случайный токен, в базе хранится его SHA-256.

## Документы и данные

Поддерживаются CSV, XLSX, DOCX и текстовый PDF по шаблонам `fixtures/`. Сначала проверка размера/формата и извлечение → preview → явное подтверждение. Дубликат файла у одного пользователя не создаёт второй blob. Статус «Загружен» только после подтверждения. Выписка даёт денежный поток; ОФР — бухгалтерскую выручку/прибыль; модель — плановые показатели. Не взаимозаменяются. Валюта RUB. В CSV выписки обязательна колонка `kind`: `operating` (операционное движение), `financing` (заёмные средства), `debt` (обслуживание долга), `transfer` (внутренний перевод). Только операционные движения участвуют в свободном потоке; платежи по долгу учитываются отдельно. Автоматическая классификация произвольного назначения платежа не заявляется. Сохраняются исходные операции и строки графика, включая даты и части платежа.

## Ограничения

Локальный хакатон-прототип, не production-сервис. Нет SMS, OCR, реальных банковских счетов/выдач/платежей/заявок, актуального банковского каталога. Нет автоматического мониторинга. LLM и DaData требуют ключей и проверки владельцем аккаунта. Загрузка произвольных банковских форм не гарантируется; шесть подготовленных fixture покрыты тестами. База локальная SQLite, без промышленного резервирования и многопроцессной миграции. Макеты использованы как семь предоставленных PNG: Figma-ссылка отсутствовала. Иллюстрации и графики построены в HTML/CSS/SVG.
