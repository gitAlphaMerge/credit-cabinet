# Кредитный кабинет v2 · 18 октября 2026

## Область и вход

Новый кабинет: **http://localhost:4173/cabinet-v2**. Прежний кабинет сохранён на **http://localhost:4173/cabinet**; между вариантами есть переходы. Глобальная навигация ведёт в новый вариант. Исходники и изменения только в `hw/tolya/alfa-intellect`, ветка `Толя`, без merge.

Основной источник требований — приложенная спецификация кредитного кабинета, затем подробное задание. Поэтому при отсутствии подтверждения кредита задолженность неизвестна, а не автоматически 0 ₽. Ноль появляется после явного подтверждения отсутствия действующих кредитов.

Новая запись `state.cabinet` необязательна: старые аккаунты читаются без удаления или перезаписи документов, переписки и подборов. Прежний `state.credit` не подменяется новым договором. Сохранённый ранее синтетический кредит может отображаться в v2 с соответствующей маркировкой; его наличие не означает реальное банковское подключение.

## Что работает

- Основной долг — главный акцент; первоначальная сумма, погашенный основной долг, прогресс, ставка, общий и оставшийся срок, дата завершения и выдачи. Условия раскрываются отдельно.
- Пользовательский сценарий добавления одного действующего кредита: договорные параметры, подтверждение, расчётный аннуитетный график либо подтверждённый оставшийся график из профиля. Это учёт существующего обязательства, не выдача и не заявка в банк.
- Ближайшая дата и сумма, дни до платежа, основной долг, проценты и комиссии при их наличии. Один список событий используется календарём, графиком, ближайшим платежом и прогнозом.
- Календарь с переключением месяцев и деталями даты. Исполнение отмечается только явно: полный платёж с датой и основанием, без изменения банковских счетов. Повторное подтверждение не уменьшает долг второй раз. Частичная оплата, переносы и банковская сверка не реализованы.
- Один постоянно видимый график основного долга: план и подтверждённое исполнение, подсказка даты/остатка, клавиатурные стрелки. Без графика — постоянная пустая область, без случайных чисел.
- Поступления, списания и чистый поток за последние 30 календарных дней по подтверждённым строкам выписки; остаток на известную дату. Неполный период отмечается. Отсутствие остатка не превращается в ноль.
- Датированный план движения денег с подтверждением полноты. Прогноз после ближайшего платежа, минимум за 30 дней, дата и сумма возможного дефицита. При недостаточных данных — объяснение, без фиктивного прогноза.
- Четыре компактных коэффициента с раскрываемыми формулами, источниками, исходными данными, периодом и интерпретацией.
- Лента до четырёх актуальных сигналов, построенная правилами, а не LLM. Пустое состояние не придумывает риски.
- Единый центр уведомлений во всех внутренних разделах: категории, счётчик непрочитанных, прочтение одного/всех, переход к связанному разделу, сохранение по пользователю, дедупликация и деактивация неактуальных сигналов. Проверка при входе/получении состояния и изменении данных; круглосуточный мониторинг не заявляется.
- «Обсудить с агентом» открывает встроенный чат, сохраняет серверный снимок контекста в существующем диалоге, не создаёт дублирующую историю и не затирает уже набранный черновик. Программный ответ явно маркируется «Демо». После перехода в отдельный чат можно вернуться в тот же вариант кабинета.
- Сохранены изменение ширины 60/40, закрытие и восстановление чата, мобильные вкладки, профиль, документы и подбор финансирования.
- Единственный существующий механизм обучения обновлён: ровно шесть шагов, реальные компоненты, несколько подсвечиваемых целей, Назад/Далее/Пропустить. На узком экране подсказка занимает отдельное место. Учебные значения создаются только в UI и не сохраняются в SQLite.

## Финансовая методика и данные

Расчёты детерминированы в `shared/cabinet.ts`; сервер и UI используют один модуль. Это отдельный заменяемый слой MVP, **не заявление о подключении рабочего ядра команды**. Существующий адаптер Go `/api/team-score` не изменён.

| Показатель | Расчёт / ограничение |
| --- | --- |
| Погашенный основной долг | Первоначальная сумма − подтверждённый текущий остаток. Прогресс применяется только к разовому кредиту. |
| Расчётный график | Аннуитет из указанного остатка, ставки и оставшегося срока; нулевая ставка поддерживается; последний платёж закрывает округлённый остаток. Даты конца месяца корректно ограничиваются длиной месяца. |
| Чистый поток | Все поступления − все списания за 30 дней. Не бухгалтерская прибыль, не CFADS; кредитные поступления не становятся выручкой. |
| DSCR | Отдельный подтверждённый CFADS / основной долг и проценты за тот же покрытый графиком период. Без CFADS — неизвестно. Ориентиры 1,0 и 1,3 взяты из спецификации, не являются нормами банка. |
| Доля платежей | Обязательства графика / денежные поступления за тот же период × 100%. Нужны полная выписка и покрытие периода графиком; универсального цветового порога нет. |
| Динамика выручки | Разница двух бухгалтерских выручек / предыдущая × 100%. Нужны границы сопоставимых завершённых периодов. При нулевой базе процент неизвестен. |
| Рентабельность продаж | Прибыль **от продаж**, не чистая прибыль / выручка × 100%. Отраслевой норматив не придуман. |
| Прогноз ликвидности | Начальный остаток + датированные поступления − расходы − обязательства. Горизонт — сегодня и следующие 29 дней. Остаток не старше 7 дней, полный план на горизонт; нерешённые прошедшие обязательства блокируют уверенный прогноз. |

Внутри дня используется консервативное допущение: расходы и платежи до поступлений того же дня. Оно указано в интерфейсе. Известное исполнение учитывается по дате факта. Это сценарий по подтверждённым пользователем предположениям, не выписка банковского баланса и не гарантия достаточности средств. Если ближайший платёж вне горизонта 30 дней, сумма после него не выдумывается.

В профиле добавлен шаблон `fixtures/pnl-comparable.csv`: выручка, предыдущая выручка, прибыль от продаж, чистая прибыль и границы периодов сохраняются раздельно. Старый ОФР без этих полей остаётся пригоден для прежних сценариев, но не даёт выдуманную рентабельность продаж. В графике поддержана необязательная колонка `fees`. Пустое значение остатка выписки больше не распознаётся как 0.

Для линии/овердрафта в модели предусмотрены тип, лимит, задолженность и доступные средства, без прогресса погашения. Полноценное добавление/обслуживание этих инструментов и нескольких договоров — следующий этап, не готовая функция MVP.

## Что ожидает внешнего подключения

- Рабочее финансовое ядро команды вместо изолированного слоя MVP и согласование методики получения CFADS из первичных документов.
- Реальные банковские договоры, счета, факт исполнения и промышленная сверка. Сейчас это только подтверждённые документы и ручные сведения.
- Живой LLM: адаптер получает детерминированный контекст, но платные запросы при разработке не выполнялись. Программный режим проверен отдельно и не выдаётся за модель.
- Фоновый планировщик/доставка push, SMS, email. В MVP уведомления обновляются при входе, чтении состояния и изменении данных.
- Произвольные банковские формы, OCR, сложные договорные календари, частичные погашения и пересогласование условий. Нынешний импорт — подготовленные шаблоны.

Для запуска: из `hw/tolya/alfa-intellect` выполнить `npm ci`, `npm run build`, `npm start`, затем войти в аккаунт и открыть `/cabinet-v2`. Не открывать исходный `index.html` через `file://`.
