# MVP 2 — финальная продуктовая корректировка

Дата: 25.10.2026. Ветка: tolya/structure-v2. Основной функциональный источник — предоставленный MVP 2.docx; последняя инструкция пользователя уточняет маршрутизацию, анонимную сессию и оформление. Исходные вложения не добавлялись в Git.

## 1. Ошибка прежней реализации

Новый процесс был встроен в старую кабинетную оболочку. До выдачи отображались глобальные вкладки обслуживания, после онбординга требовалась регистрация, справа стояла информационная карточка вместо постоянного чата. Положительное прохождение backend-пути ошибочно считалось подтверждением всей продуктовой структуры.

Исправление меняет основной клиентский интерфейс, а не добавляет ещё один режим поверх прежнего.

## 2. Layout, маршруты и доступ

- До выдачи App показывает отдельную оболочку origination: логотип, обозначение оформления, текущий этап, контент и переходы. Кабинетных вкладок нет.
- Основные клиентские URL: /, /onboarding, /apply; после выдачи — /cabinet и /chat.
- Старые /demo, /login, /financing, /application, /calculations, /legacy-application и кабинетные алиасы не открывают старые пользовательские экраны.
- Серверная обработка страниц перенаправляет неразрешённые URL. До выдачи /cabinet, /cabinet-v2, /efficiency, /chat и другие обслуживающие адреса возвращают к оформлению.
- Доступ определяется по сохранённой ACTIVE-заявке, операции выдачи/открытия лимита, согласованной подписи и версии договора. Изменение frontend-флага, профиля или объекта cabinet не является основанием доступа.
- Участники нового пути до активации не могут использовать старые ручные кабинетные/калькуляторные API для обхода конвейера.
- Менеджерское рабочее место осталось отдельным ролевым пространством. Роль проверяется сервером; назначить её из клиентской анкеты нельзя.

Старые backend-модули сохранены для совместимости и технических проверок, но не образуют второй пользовательский маршрут.

## 3. Единый пользовательский путь

Landing → семь вопросов → предварительная рекомендация/каталог → ознакомление → пять разделов анкеты → клиентское досье → серверный конвейер → решение.

Далее:

- APPROVED: договор → отдельная подпись → отдельное «Получить деньги» → существующий кабинет.
- MANAGER_REVIEW_REQUIRED: запись на встречу → решение менеджера; предварительная оценка не открывает договор и кабинет.
- ADDITIONAL_DATA_REQUIRED: только конкретные недостающие поля → повторная оценка той же заявки.
- DECLINED: проверенная альтернатива с новой оценкой либо объяснение/консультация; блокирующий комплаенс не получает обходных альтернатив.

Порог маршрутизации остаётся на backend: положительная оценка до 3 млн руб. включительно — автоматический маршрут; свыше — менеджер. В ядро порог не переносился.

## 4. Анкета 60/40 и агент

На десктопе реальная ширина колонок — 3fr/2fr. Слева пять разделов с условными полями и переходами; справа полноценный чат: история, ввод, отправка, примеры вопросов и подсказка по разделу. Можно задавать вопросы, не покидая анкету. На узких экранах блоки адаптивно располагаются последовательно.

Ознакомление использует ту же компоновку и не требует ввода. После решения кнопка обсуждения открывает полноэкранный режим того же контекстного диалога; есть возврат к решению. Это не глобальная вкладка чата в процессе оформления.

ApplicationAgent использует существующий endpoint обсуждения конкретной заявки и существующего провайдера. Раздел передаётся перед отправкой, история хранится на сервере. Языковая модель не меняет решение и не рассчитывает лимиты. При недоступности модели вопрос сохраняется, показывается понятная ошибка, а ответ не подменяется шаблоном.

## 5. Визуальные изменения

- Сохранены тёмная палитра, коралловый акцент, типографика, компоненты и анимация LivePattern.
- Лендинг больше не содержит наложенных финансовых карточек, сценовых переключателей, подписи продавца и demo-входов; анимация крупно расположена справа.
- Убраны декоративный блок «От задачи к понятным условиям», белые квадратные иллюстрации онбординга/анкеты и обязательные ссылки входа.
- Сумма онбординга выбирается ползунком по семи диапазонам. «Пока не знаю сумму» остаётся отдельным явным вариантом, без подмены неизвестного нулём.
- Проценты кругового индикатора белые, без multiply-смешивания. Вычисленный цвет проверен при 0/50/100%.
- Тёмная тема стала исходной; ручной выбор светлой сохраняется и синхронизируется. Исправлен контраст активного раздела.

## 6. Анонимная сессия и данные

Нет обязательного телефона, пароля, SMS, OTP или экрана регистрации. Backend автоматически выдаёт криптографический токен в HttpOnly/SameSite cookie. Для совместимости существующего хранилища создаётся технический владелец anonymous с запрещённым паролем, не пользовательский аккаунт с контактами.

На сервере сохраняются:

- ответы и шаг онбординга;
- связь с заявкой и её текущий экран/раздел;
- промежуточный черновик, включая незавершённое поле;
- основные данные, документы, решения, встреча, подпись и операция активации.

Private draft buffer не является скоринговым досье: неполный ИНН или незавершённая сумма могут сохраняться, но не подменяют валидированные данные заявки. Перед расчётом действует прежняя строгая серверная проверка. Буфер связан с владельцем и версией; чужое чтение запрещено, устаревший буфер не применяется.

Новые банковские реквизиты и документы не записываются в localStorage/sessionStorage. Прежний совместимый буфер при наличии переносится в серверное хранилище и удаляется из браузера. После активации та же сессия впервые получает доступ к кабинету.

## 8. Оставшиеся ограничения

- Реестр, БКИ/комплаенс, встречи, подпись и зачисление синтетические по рамке MVP; реальные банковские сервисы не подключались.
- В локальном просмотре внешняя LLM не настроена. Интерфейс и интеграция чата доступны, но живой ответ требует существующего настроенного провайдера. Offline не выдаётся за анализ модели.
- Сессия живёт по существующему TTL 7 дней. Очистка cookie или другое устройство не восстанавливают владельца без отдельной системы аккаунтов; такая система намеренно не разрабатывалась.
- Сохранение требует соединения с сервером; при ошибке показывается предупреждение. Полноценного offline-редактора нет.
- Неизменённые золотые сценарии финансового ядра ранее дали 4/8 и на чистом исходном main. Эта проблема владельца ядра не скрывается успешными UI/API-тестами и не исправлялась здесь.
- Механика открытия кредитных линий/овердрафта сохраняет нулевой долг до выборки. Полный траншевый ledger и реальные внешние переводы при рефинансировании не добавлялись.
- Встроенный просмотр PDF зависит от поддержки PDF браузером; скачивание обоих PDF доступно отдельно. Юридически значимая подпись отсутствует.

Финансовое ядро, защищённая интеграция агента и инфраструктурные настройки в этой корректировке не переписывались. Изменения предназначены для PR и ревью, не для прямого вливания в main.
