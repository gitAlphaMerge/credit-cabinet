# MVP 2 — реализация и проверка

> Исторический отчёт первой реализации. Описание прежней оболочки и обязательной регистрации ниже больше не является актуальной продуктовой структурой. Итоговая корректировка и текущие проверки: [MVP2_FINAL_CORRECTION.md](MVP2_FINAL_CORRECTION.md).

Дата проверки: 25.10.2026. Основа: `origin/main`, `5e06791`.
Рабочая ветка: `tolya/structure-v2`. Прямых изменений и публикаций в `main` нет.

## Сквозной путь

1. Семь ответов онбординга на трёх экранах → существующая регистрация.
2. Предварительная рекомендация → ручной выбор любого из шести продуктов → вводная 60/40.
3. Пять разделов анкеты: компания, финансы, обязательства, особенности, финансирование.
4. Клиентское досье с раскрытием сведений и редактированием до подачи.
5. Серверная обработка с сохраняемыми этапами → одно из четырёх решений.
6. До 3 млн руб. включительно при положительной оценке — автоматическое одобрение; свыше — запись на встречу и окончательное решение менеджера. Порог 5 млн не используется.
7. Адресный дозапрос → только нужные поля → повторные проверки. Проверенная альтернатива также запускает новую оценку.
8. Реквизиты → два PDF → отдельное подписание зафиксированной версии → отдельная активация → существующий кредитный кабинет.

Новый глобальный деморежим не создан. Прежние расчёты и исторические заявки доступны отдельно по ссылкам `/calculations` и `/legacy-application`; старый конвейер не может подписать или выдать MVP2-заявку в обход новых проверок.

## Границы интеграции агента

По отдельному согласованию владельца изменены только `services/agent/dialog.py` и `services/agent/server.py`: заявки MVP2 вызывают существующий языковой слой с сохранённым контекстом. Страж проверяет числа, обещания, ПДн и формат. При отсутствии/ошибке модели или небезопасном ответе возвращается недоступность, а не шаблон под видом анализа. Старые режимы агента сохранили прежний контракт.

`TeamAgentProvider`, сборка agentCard, порядок выбора провайдеров, автозапуск агента, Go API, финансовое ядро и защищённые существующие тесты не изменены. Контекст проходит allowlist и маскирование известных реквизитов/имён/телефонов/email; досье, исходные CSV, счета и компания целиком модели не отправляются. Передача обезличенного контекста отдельно разрешена пользователем.

Для работы объяснений нужен существующий `TEAM_AGENT_URL` и настроенная модель `AGENT_LLM_URL`/`AGENT_LLM_MODEL`/ключ, либо явно выбранный существующий OpenAI-провайдер. При недоступности можно продолжать заполнение и рассмотрение заявки. В проверках внешние платные модели не вызывались: использованы локальный транспорт и внедряемые ответы модели.

## API и хранение

Новый защищённый namespace: `/api/mvp2`. Основные ресурсы: `catalog`, `applications`, `applications/:id` (GET/PUT), `registry`, `statements`, `submit`, `alternative`, `recalculate`, `meeting`, `contract-details`, `contract`, `sign`, `activate`, `documents/:kind`, `chat`. Менеджер: `GET /manager`, `POST /manager/:id/decision`; календарь: `GET /slots`.

Миграция 6 добавляет таблицы `mvp2_dossiers`, `mvp2_revisions`, `mvp2_checks`, `mvp2_statements`, `mvp2_slots`, `mvp2_documents`, `mvp2_disbursements` поверх существующей БД. Чужая заявка/документ недоступны; права менеджера проверяются сервером; устаревшая версия отклоняется. Лимиты размера файлов/числа операций, дубли запросов и выдача обрабатываются сервером.

## Запуск

Обычный командный стенд: из корня `docker compose up --build api ml-model agent alfa-intellect`. Используются существующие порты, volumes и `mem_limit`, без изменений compose.

Для локальной проверки без Go-шлюза можно запустить неизменённое ядро напрямую в отдельном терминале:

```sh
CORE_ID=liza PORT=5001 python3 services/ml-model/app.py
```

Затем из `hw/tolya/alfa-intellect`:

```sh
npm ci
npm run build
TEAM_API_URL=http://127.0.0.1:5001 TEAM_AGENT_URL=http://127.0.0.1:8090 PORT=4174 npm start
```

Внешняя модель и ключи задаются существующей конфигурацией агента, секреты в репозиторий не помещать. Роль менеджера выдаётся существующим доверенным административным механизмом, не клиентским запросом. На Linux генератору PDF нужен DejaVu Sans; Dockerfile устанавливает его. Можно явно задать `CONTRACT_FONT` на подходящий локальный шрифт.

## Оставшиеся ограничения

- Это сквозной учебный MVP: реестр, БКИ, комплаенс, календарь, подпись и зачисление синтетические. Нет реальной заявки в банк, юридически значимой ЭП и движения денег. В документах это обозначено явно.
- Непроходящие 4 золотых сценария исходного ядра остаются отдельной задачей Лизы/Саши. Финансовое ядро не переписывалось; успешные unit/API/UI-тесты не заменяют этот факт.
- Каталог MVP отличается от банковского каталога ядра. Для REFI его MANUAL-инструмент не трактуется как самостоятельный финансовый отказ: адаптер использует текущую консервативную ёмкость Лизы, цену каталога MVP и проверку нагрузки. Это не подтверждение банковской доступности REFI. `limit_after` не повышает одобренную сумму.
- Для линий нагрузка при оценке — консервативный месячный эквивалент, явно не обязательный аннуитет. Открытие лимита реализовано; полноценные выборки/револьверный ledger и внешний перевод кредитору при REFI не входят в активацию. Чужой реальный кредит автоматически погашенным не помечается.
- Анализатор CSV проверяет структуру и согласованность, а не подлинность банковского документа. Оценка полноты зависит также от подтверждения пользователя. Будущие события и сведения вне выписки не выдаются за подтверждённые поступления.
- Локальный E2E ходил прямо в сервис Лизы через существующий HTTP-клиент; контейнерный Go-шлюз и продуктивные провайдеры в этом прогоне не разворачивались. Docker image в этой среде не собирался.
- Обработка возобновляется при чтении заявки; отдельного распределённого worker/очереди нет. SQLite-транзакции защищают локальный экземпляр, но это не доказательство горизонтальной масштабируемости.
- Проверены критические маршруты и регрессии, а не все сочетания устройств, браузеров и банковских CSV. В production без демоперсон остаётся существующий 404 запроса `/api/demo-personas`; ошибок выполнения страницы в E2E нет.

Исходные вложения изучены, но остаются вне Git. Юридический текст фиксирован в `server/mvp2-contracts.ts`, а не дописывается моделью.
