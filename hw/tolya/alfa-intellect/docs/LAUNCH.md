## Запуск и проверка за 5 минут

Основной путь: корневой compose, Docker с Linux-контейнерами. Из корня репозитория:

```sh
docker compose up -d --build api alfa-intellect
cd hw/tolya/alfa-intellect
node scripts/smoke.mjs --base http://localhost:4173
```

Открыть http://localhost:4173 или http://localhost:4173/demo. Команда поднимает
также `ml-model` по зависимости Go API. Сайт обращается к `http://api:8080`
внутри Docker, без `host.docker.internal`. Адаптер ядра: защищённый
`POST /api/team-score`. Обычный подбор в UI использует локальную демонстрационную
модель, это не результат ядра Лизы.

Первичная сборка требует заранее доступных Docker-образов и npm-зависимостей
(`npm ci` сохранён). Для ПК без сети подготовьте образы на машине сборки,
перенесите через `docker save` / `docker load`, затем запускайте:
`docker compose up -d --no-build api alfa-intellect`. Наличие `node_modules`
на хосте не заменяет зависимости внутри образа. Dockerfile закреплён на
`node:24.0.0-slim`, версии из `engines`. Smoke требует только Node 24 и stdlib.

Для проверяемой версии ключи и внешние сервисы не нужны. Корневой compose
не передаёт ключи, ЕГР работает в `mock`. Чат без ключей работает на шаблонах,
внешняя LLM не вызывается. OpenAI не входит в проверяемую версию. Если отдельно
подключаете LLM агента, используйте только разрешённые кейсом открытые веса.
Python-агент не упакован в образ сайта; его необязательное подключение остаётся
отдельным контрактом команды.

SQLite и документы сохраняются в volume `alfa_data` (`/app/var`). Перезапуск:
`docker compose restart alfa-intellect`. Логи: `docker compose logs --tail=80 alfa-intellect`.
Для другого порта задайте `ALFA_PORT` и передайте тот же порт в `--base`.
Сайт перезапускается автоматически. `/health` и `/api/health` возвращают 200 JSON:
`status`, `db: ok|fail`, `team_api: ok|down|not_configured`. Go API проверяется
с таймаутом 2 с, его отказ не делает сайт unhealthy. Отказ БД даёт `degraded`
и учитывается Docker healthcheck. Healthcheck сам по себе не перезапускает контейнер.
`depends_on: service_started` задаёт порядок запуска, недоступность уже запущенного
API не блокирует сайт. Отказ адаптера возвращает понятный JSON 502 за 30 с.

Smoke печатает OK/FAIL и возвращает exit 1 при ошибках. Создаёт синтетического
пользователя в выбранной базе, записи сохраняются. Недоступное ядро допускается
только как понятный JSON 502. Для полного стыка дополнительно убедитесь, что
`/health` показывает `team_api: ok`. Сумма лимитов корневого compose теперь
768 МБ: сайт добавляет заданные 256 МБ, существующие сервисы сохранены.

### Какие данные синтетические

`fixtures/egr-mock.json`: четыре вымышленные записи. Номера предназначены только
для мока, их контрольные цифры не подтверждают регистрацию:

| ИНН | Форма | Статус | ОКВЭД |
| --- | --- | --- | --- |
| 9900000001 | ООО | Действующая | 31.09 |
| 9900000002 | ООО | Ликвидирована | 46.73 |
| 990000000001 | ИП | Действующий | 62.01 |
| 990000000002 | ИП | Прекратил деятельность | 56.10 |

Ответ и UI показывают «синтетические данные (мок)», в том числе после сохранения
в профиле. Неизвестный номер даёт 404 с подсказкой. Мок выбирается без ключей
реестра или явно `EGR_PROVIDER=mock`. Для реального провайдера уберите `mock`
и задайте ключ. Сбой реального провайдера не подменяется моком. Публичное демо,
каталог ставок и подготовленные документы также синтетические, не являются
банковским решением или подтверждением сведений государственного реестра.

Локальный `compose.yaml` оставлен для отдельного запуска сайта. Его прежний
`TEAM_API_URL` с `host.docker.internal` требует настройки хоста на Linux;
основной путь этого адреса не использует. Для проверки используйте корневой compose.
