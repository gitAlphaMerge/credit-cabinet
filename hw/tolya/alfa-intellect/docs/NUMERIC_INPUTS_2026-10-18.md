# Читаемый ввод сумм и сроков · 18 октября 2026

По пяти замечаниям к форме «Добавить действующий кредит»:

- Денежные поля форматируются во время ввода: `1 250 000,50` и отдельный суффикс `₽`. Пробелы не входят в сохраняемое значение. Поддержаны вставка числа с рублями/NBSP, точка или запятая для копеек, выделение, вставка в середине, Backspace/Delete возле разделителей. Буквы, экспоненциальная запись и лишние дробные знаки отклоняются, а не округляются молча.
- Общий компонент `NumericInput` используется в кредите, плане и CFADS, денежных полях подбора и `RangeField` публичного демо/подбора. Отрицательные значения разрешены только там, где допустимы: денежный поток и плановые операции. Минимумы/максимумы и мобильная цифровая клавиатура сохранены.
- Сроки — целые числа с видимым суффиксом `мес.`, ставка — с `%`.
- «Ближайшая договорная дата» заменена на «Дата ближайшего платежа» с пояснением. Произвольная дата +10 дней больше не подставляется: пользователь вводит дату своего графика.
- «Откуда взять график платежей?» предлагает расчёт по введённым данным либо уже загруженный график банка. Пояснение указывает путь «Мой бизнес → Документы».
- Убраны чекбокс и текст подтверждения из формы кредита. Кнопка — «Сохранить кредит». Это по-прежнему ручной учёт существующего обязательства, не выдача кредита и не банковская проверка. Необязательные общий срок/дата выдачи при пустом значении не отправляются как 0 или фиктивная дата. Подтверждения полноты денежного плана и извлечённых документов не удалялись.

## Проверка

`npm run verify`: форматирование, TypeScript, production build и 77/77 тестов. Шесть новых тестов покрывают нормализацию/форматирование, копейки, знаки, отклонение неправильного ввода, месяцы, позицию курсора и HTML поля.

`scripts/check-unified-cabinet.cjs` — полный сценарий кабинета с новой формой без чекбокса, календарём, документами, уведомлениями, агентом и адаптивностью. `scripts/check-numeric-inputs.cjs` — отдельный браузерный прогон: вставка рублей/NBSP, копейки, редактирование середины числа, Delete/Backspace, положительная сумма, сохранение без чекбокса, точные значения API и после reload, оформление на 390 px, ограничения ползунка и их отображение при фокусе, копейки при числовом состоянии, отрицательный поток и восстановление черновика.

Оба браузерных прогона успешны, ошибок JavaScript нет. Тесты — только на 4174 с временной SQLite `/private/tmp/alfa-inputs.*`, пользовательская база 4173 не использовалась для тестовых записей. Платных LLM-запросов и банковских действий не было. Тестовые сервер/браузер закрыты после проверки; основной сайт оставлен на 4173.
