## Открытые ограничения

**Python CI: конфликт актуального main и теста.** Проверка приложения `cabinet` в GitHub прошла. Python job упал в `services/ml-model/tests/test_properties.py:157`: ожидается «лучше другой инструмент» для TOO_YOUNG, фактический ответ — «нужен менеджер». После `git fetch origin main` установлено: свежий `main` `5c261ee` перенёс TOO_YOUNG в behavioral stops, тогда как локальная контрольная точка и тест содержат прежнее ожидание. Проверка PR на объединении с main обнаружила это расхождение. Нужна согласованная правка в зоне ядра: ожидание `test_properties.py` и принятое владельцем правило должны совпадать. Защищённые файлы ядра/его тестов в рамках стабилизации не изменялись; CI не объявляется зелёным и PR не сливался.

**Золотой экзамен ядра: 4/8.** `python3 data/check_golden.py` запущен на текущем коде и на отдельно извлечённой контрольной точке `46c38b4`; результаты совпали полностью. Не проходят `cash_gap_small`, `equipment_leasing`, `short_history`, `cash_out`. Изменений в ядре, каталоге и банковском решении нет. Причины и ожидаемые инструменты расходятся с существующим эталоном; это требует согласования владельца ядра, а не изменения frontend. Общая готовность проекта не объявляется только по зелёным UI-тестам.

Живой LLM локально недоступен; контекстный запрос и ошибка не подменяются заранее заданным ответом. Синтетический реестр, демонстрационная подпись/выдача и локальная запись обращения сохраняют рамку MVP. Внешняя отправка в банк не подключалась.

Просмотр PDF проверен в Chromium, включая эмуляцию мобильной ширины. Это не отдельная проверка на физическом Safari/iOS. Сборка сохраняет предупреждение Vite о размере JS-бандла; переразбиение приложения ради него не выполнялось.
