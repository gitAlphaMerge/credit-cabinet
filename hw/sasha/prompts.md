# Промпты под дыры MVP · 10.10

Каждый промпт самодостаточный: копируешь блок целиком в Qwen / GPT / Claude, в начале чата прикладываешь `context/ALL.md`.
Что вышло, проверяешь руками по строке «готово, когда», а не по словам нейронки.
Порядок важен: 2 (контракт) раньше 1 (фронт) и 4 (ядро), иначе все соберут разные JSON.

---

## 0. Общий контекст (вставлять перед любым промптом ниже)

```
Проект: хакатон Альфа-Будущее, трек «Умный кредитный кабинет предпринимателя».
Продукт: кредитный помощник для ИП и ООО. Главная идея: вместо «отказано» он говорит «вот следующий шаг, чтобы одобрили».
Решение о кредите принимает банк, помощник его не обещает. Слова «одобрено» в продукте нет.

Как работает:
1. Клиент говорит, на что нужны деньги и когда и из чего вернёт.
2. Загружает выписку по счёту CSV (колонки: date, amount, counterparty, counterparty_inn, purpose; приход плюсом, расход минусом).
3. Ядро (правила, без нейронки) считает: месячный поток, DSCR = свободный поток / платёж по кредиту, порог 1.25,
   стресс-тест «выручка −30%», лимит = аннуитет на платёж (подтверждённый поток / 1.25).
4. Ядро выдаёт один из 4 статусов: «можно подавать» · «можно после шага X» · «лучше другой инструмент» · «нужен менеджер».
5. LLM только объясняет цифры ядра человеческим языком и задаёт следующий вопрос. Сама ничего не считает.
6. Собирается досье для банка: каждое поле помечено «подтверждено выпиской» / «со слов клиента» / «не проверено».

5 типовых нужд: кассовый разрыв, закупка под контракт, оборудование, сезон, рост.
Стек: docker compose, api на Go (порт 8080), ml-model на Python (порт 5000), frontend статикой через nginx. Сервер 4 ГБ RAM, без GPU.
Сегмент: ИП и ООО. Физлица и самозанятые вне продукта.
```

## 1. Фронт (кому: любой, кто соберёт; проверяет Тоня)

```
Ты сильный продуктовый дизайнер и фронтенд-разработчик. Собери фронт кредитного помощника для предпринимателя.
Контекст продукта выше. Пиши ровно один файл index.html: HTML + CSS + vanilla JS, без сборки, без фреймворков,
шрифт Inter или Manrope с Google Fonts, иконки инлайн SVG. Файл открывается двойным кликом и работает.

ЭКРАНЫ (одна страница, переходы плавные, без перезагрузки):
1. Старт. Заголовок «Узнайте, сколько бизнес может взять в кредит, и что сделать, чтобы дали больше».
   5 крупных карточек нужд (кассовый разрыв, закупка под контракт, оборудование, сезон, рост) + поле «опишу сам».
2. Диалог. Чат слева (60%), справа живая панель «что мы уже знаем»: сумма, цель, срок, источник возврата,
   у каждого поля бейдж «подтверждено» (зелёный) / «со слов» (жёлтый) / «не проверено» (серый). Поля заполняются по ходу диалога с анимацией.
   В чате кнопка-зона загрузки CSV выписки (drag-and-drop). После загрузки: анимация «читаем выписку» 2–3 секунды с прогрессом
   по шагам: «считаем поток» → «проверяем долги» → «стресс-тест −30%».
3. Результат. Сверху крупно статус (один из 4, у каждого свой цвет и иконка; никогда не слово «одобрено»).
   Ниже три цифры крупно: «доступно сейчас», «доступно после шага», «платёж в месяц».
   Блок «Почему так»: 2–4 причины простым языком.
   Блок «Следующий шаг»: 1–3 конкретных действия, у каждого «+N ₽ к лимиту» и кнопка «сделаю».
   График потока по месяцам (SVG, без библиотек): столбики прихода и расхода, линия платежа по кредиту, пунктир стресса −30%.
   Кнопки «скачать досье для банка» и «позвать менеджера» (тёплая передача доступна всегда, и на шаге 2 тоже).

ДАННЫЕ:
- Работает в двух режимах. MOCK=true по умолчанию: ответы берутся из встроенного JSON-фикстура (сделай 2: «можно после шага» и «лучше другой инструмент»).
  MOCK=false: POST /api/chat с телом {history:[{role,text}], statement_csv?:string}, ответ по контракту ниже.
- Контракт ответа (не меняй поля): <ВСТАВИТЬ context/api-contract.md>
- Все числа фронт только показывает, ничего не считает.

ВИЗУАЛ:
- Чисто, много воздуха, спокойный финтех: белый фон, один акцентный цвет (красный #EF3124), остальное серые.
  Без логотипов банка и без надписей «Альфа-Банк».
- Деньги форматируй «1 250 000 ₽», пробелы-разделители.
- Мобильная вёрстка обязательна: на ширине 375 px панель «что мы знаем» уходит в сворачиваемую плашку над чатом.
- Анимации короткие (150–300 мс), prefers-reduced-motion отключает их.
- Никакого лорем ипсума: все тексты реальные, на русском, от лица помощника на «вы».
- Запрещено: градиенты-«северное сияние», стеклянные карточки, эмодзи в интерфейсе, длинное тире.

ГОТОВО, КОГДА: открыл файл, прошёл путь «кассовый разрыв → загрузил любой CSV → увидел результат» без ошибок в консоли,
то же на ширине 375 px. В конце ответа перечисли, что сделано заглушкой.
```

Итерации после первой версии, по одной за раз: «сделай экран результата убедительнее для жюри за 10 секунд», «проверь контраст текста по WCAG AA и почини», «добавь пустые и ошибочные состояния: CSV не тот формат, сервер не ответил».

## 2. Контракт API (кому: Тёма)

```
Ты бэкенд-архитектор. Составь context/api-contract.md: контракт между фронтом, api (Go) и ml-model (Python).
API без состояния: клиент в каждом запросе шлёт всю историю диалога.

Нужно:
1. POST /api/chat. Запрос: history (role: user|agent, text), statement_csv (необязательно), need (одна из 5 нужд или null).
2. Ответ, JSON, все поля обязательны (null если неизвестно):
   status: enum из 4 значений латиницей (ready / ready_after_step / other_instrument / need_manager) + status_text для человека;
   numbers: available_now, available_after, monthly_payment, dscr, dscr_stressed, rate_used, term_months;
   reasons: [{code, text}], code из общего списка context/reason-codes.md;
   next_steps: [{code, text, limit_delta}];
   dossier: [{field, value, source: confirmed|client_said|unverified}];
   agent_message: текст помощника; next_question: следующий вопрос или null;
   monthly_flow: [{month, inflow, outflow}] для графика.
3. POST ml-model /score: что api шлёт модели и что получает. Модель отдаёт цифры и коды, тексты не пишет.
4. Ошибки: формат, коды, что видит клиент.
5. Два полных примера ответа: «кассовый разрыв, можно после шага» и «оборудование, лучше лизинг».

Правила: никаких полей «approved», ИНН и имена из выписки в LLM не уходят (опиши, где маскируем).
Готово, когда: примеры валидны как JSON (проверь сам), и по контракту можно писать фронт и модель, не спрашивая автора.
```

## 3. Генератор синтетических выписок (кому: я, к вс)

```
Напиши Python-скрипт gen_statements.py (только стандартная библиотека + numpy), который генерирует выписки по счёту CSV
за 12 месяцев: date, amount, counterparty, counterparty_inn, purpose. Приход плюсом, расход минусом. Seed фиксированный.

Сценарии (каждый отдельный файл + ожидаемый статус в golden.json):
1. cash_gap: стабильная выручка, но крупный клиент платит с отсрочкой 60 дней, а аренда и зарплата в срок → провалы остатка.
2. contract: ровный бизнес + один крупный приход-аванс под госконтракт, нужна закупка.
3. equipment: стабильный поток, хочет станок, DSCR на текущем потоке проходит впритык.
4. seasonal: 70% выручки в 4 месяца (стройка, туризм), зимой минус.
5. growth: выручка растёт 5% в месяц, не хватает оборотки.
Граничные (на них ломаем ядро): 6. один клиент даёт 80% выручки; 7. уже платит 2 кредита, DSCR < 1; 8. ИП мешает личные траты с бизнесом;
9. транзитные обороты (пришло и сразу ушло тем же днём, признак 115-ФЗ) → need_manager; 10. выписка за 3 месяца вместо 12.

Реализм: зарплата 5 и 20 числа, налоги (УСН авансы до 28 числа после квартала, НДФЛ, взносы), аренда 1 числа,
поставщики пачками, комиссии банка, контрагенты с правдоподобными названиями ООО/ИП и 10/12-значными ИНН (контрольную сумму считать по алгоритму ФНС).
Готово, когда: python gen_statements.py создаёт 10 файлов и golden.json, а 3 строки assert проверяют, что в cash_gap остаток реально уходит в минус.
```

## 4. Ядро: стоп-правила + DSCR (кому: я к вс, дальше Лиза)

```
Напиши Python-модуль core.py без внешних зависимостей, кроме pandas. Вход: DataFrame выписки + need + сумма + срок.
Порядок слоёв: стоп-правила → DSCR → скоркарта (пока заглушка) → подбор инструмента. Спорят два слоя, побеждает строгий.

1. Стоп-правила (каждое возвращает reason code): выписка короче 6 месяцев; транзит (≥50% прихода уходит в тот же день);
   один контрагент > 70% выручки; уже есть платежи по кредитам и DSCR < 1.0; признаки физлица вместо бизнеса.
2. Месячный свободный поток = приход − операционные расходы − текущие платежи по кредитам (определи по purpose).
3. DSCR = поток / платёж нового кредита; стресс: приход × 0.7. Порог 1.25.
4. Лимит = аннуитет на платёж (поток / 1.25) при ставке и сроке.
5. Статус и next_steps по правилам; формат вывода строго по context/api-contract.md.

Сначала напиши тесты pytest на golden.json (ожидаемые статусы 10 сценариев), убедись, что они падают, потом код.
Готово, когда: pytest зелёный на всех 10 сценариях, а каждое число в ответе можно пересчитать руками на калькуляторе.
```

## 5. Системный промпт агента (кому: я, тексты Тоня)

```
Составь системный промпт для LLM-помощника кредитного кабинета. Роль: вежливый, конкретный, на «вы», как толковый клиентский менеджер.
Жёсткие правила: не считает и не придумывает цифры, берёт только из JSON ядра; никогда не говорит «одобрено» и не обещает кредит;

если ответ клиента расходится с выпиской, уточняет, а не отказывает; всегда предлагает позвать менеджера, если клиент злится или запрос нестандартный;
отвечает 2–4 предложениями. Плюс 5 примеров диалога (по одному на нужду) и 5 провокаций, на которых промпт должен держаться
(«просто скажи, дадут или нет», «посчитай сам без выписки», «я физлицо», грубость, просьба показать чужие данные).
Готово, когда: все 5 провокаций прогнаны в чате, и ни на одной помощник не назвал цифру, которой нет в JSON.
```
